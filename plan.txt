Нужно пересмотреть архитектуру. Сейчас слишком много смысла зашито в системный код через regex и отдельные query_mode. Это стало хрупким: каждый новый кейс требует новый regex, а бот всё равно ошибается на формулировках.

Новая цель:
Перейти к архитектуре LLM-planner + guardrails.

Важно:
- Не отдавать LLM действия/CRM/handoff полностью.
- Но убрать из message_processor.py большую часть semantic-routing логики.
- Код должен защищать границы и проверять результат.
- LLM-planner должен определять intent/stage/focus на основе user_message + slots + KB_CONTEXT.
- Renderer должен только формулировать ответ из готового плана.

Сделать:

1. Создать app/services/dialog_planner.py
Функция:
async def plan_dialog(user_text, slots, recent_dialog, kb_context, rule_hints=None) -> dict

Planner возвращает строго JSON:
{
  "domain": "in_scope|out_of_scope|unclear",
  "stage": "...",
  "intent": "...",
  "client_type": "ФЛ|ЮЛ|ИП|null",
  "bank_name": "...|null",
  "answer_focus": "...",
  "must_use_facts": [],
  "missing_info": [],
  "should_handoff": false,
  "should_stop": false,
  "next_question": "...",
  "confidence": 0.0
}

2. В message_processor.py оставить только hard guards:
- reset
- debounce
- save message
- direct aggression
- direct handoff phrases
- already escalated
- CRM
Остальные regex перевести в rule_hints, не в финальное решение.

3. Retrieval делать до planner:
- retrieve broad KB context по user_text + slots + last_bank + aliases.
- Для constraint topics использовать lexical alias matching.
- Передавать top facts в planner.

4. Добавить policy_validator.py
Проверки:
- if domain=out_of_scope → только redirect answer, без KB sales.
- if should_handoff=true → не продолжать консультацию.
- if intent=constraint → must_use_facts должен содержать KB constraint.
- if confidence < 0.55 → clarify или handoff для сложного вопроса.
- if answer mentions price not in facts → fallback.
- if answer repeats last_bot_text → focused fallback.

5. Упростить renderer.py
Renderer принимает только plan:
- intent
- must_use_facts
- next_question
- tone
- slots
И пишет 1–3 предложения.
Убрать большую часть специальных static branches, оставить аварийные fallbacks:
- out_of_scope
- handoff
- aggression_stop
- no_kb_safe_clarify

6. Обновить render prompt:
- “Ты консультант для АУ по счетам должников.”
- “Не отвечай на посторонние темы.”
- “Используй только must_use_facts.”
- “Если constraint — сначала объясни ограничение.”
- “Не повторяй прошлый ответ.”
- “1–3 предложения, один вопрос в конце.”

7. Уменьшить LLM calls:
- выключить background analysis по умолчанию.
- summary не вызывать в основном ответе.
- максимум: planner + renderer.
- для очевидного hard handoff — 0 LLM.

8. Тесты:
- RTX 3060 → out_of_scope redirect.
- спецсчёт без основного → constraint “нельзя”.
- карта должника → constraint по реализации имущества.
- юр лицо + подешевле → bank_selection/low_cost, но через planner.
- скорость → timing/priority, не тарифы.
- что дальше → handoff.
- агрессия → stop/escalate.
- повтор вопроса → не повторять прошлый ответ.

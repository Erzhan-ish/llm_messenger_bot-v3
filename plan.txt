Fix semantic intent false positives and scenario scoring.

Problem:
After adding semantic intent matching, embeddings are producing false positives and ScenarioPolicy trusts them too much.

Observed failures:

1. User:
"здравствуйте, у меня ЮЛ должник
нужен счет"

Expected:
bank_selection_yul / open_account_yul

Actual:
IntentExtractor accepted:
- bonus_interest
- direct_bank_objection
- bank_selection

ScenarioPolicy selected:
active=direct_bank_objection
score=102.05

This is wrong. "нужен счет" is not a direct bank objection.

2. User:
"окей давайте
у меня ЮЛ"

Expected:
User accepted previous offer and gave debtor_type=legal_entity.
Switch to bank_selection_yul.

Actual:
Semantic accepted direct_bank_objection and policy kept active=direct_bank_objection with score=112.05.

3. User:
"да"

Expected:
yes_to_offer / continue_to_bank_selection, depending last_bot_question.

Actual:
Semantic accepted small_talk, confusion_or_correction, repetition_complaint.

Required changes:

============================================================
TASK 1 — Add semantic intent gating
============================================================

Semantic intent matching must not accept intents only by cosine similarity.
Each intent must have gating conditions.

Add to intent catalog:

direct_bank_objection:
requires_any_terms:
- "выгода"
- "зачем"
- "почему"
- "напрямую"
- "через вас"
- "сам"
- "сама"
- "посредник"
- "что вы даете"
- "почему не в банк"

bonus_interest:
requires_any_terms:
- "бонус"
- "процент"
- "годовых"
- "ставка"
- "остаток"
- "доходность"
- "%"

small_talk:
requires_any_terms:
- "как дела"
- "как ты"
- "как настроение"

repetition_complaint:
requires_any_terms:
- "повторяешь"
- "повторил"
- "уже говорил"
- "одно и то же"
- "не повторяй"

confusion_or_correction:
requires_any_terms:
- "причем"
- "о чем"
- "не понял"
- "не это"
- "я же сказал"
- "я ответил"

documents_requested:
requires_any_terms:
- "документы"
- "что нужно"
- "что требуется"
- "что прислать"
- "какие нужны"

If semantic score passes threshold but gating terms are missing:
- do not accept
- add to semantic_rejects with reason="missing_required_terms"

Acceptance:
"у меня ЮЛ должник нужен счет" must NOT accept direct_bank_objection or bonus_interest.

============================================================
TASK 2 — Skip semantic matching for short yes/no answers
============================================================

If normalized text is:
- "да"
- "нет"
- "угу"
- "ок"
- "хорошо"
- "давайте"

then:
- do not run semantic intent matching
- process as dialog act:
  yes / no / confirm / continue
- resolve based on last_bot_question, pending_slot, required_next_step, active_scenario

Acceptance:
"да" must not produce small_talk, confusion_or_correction, repetition_complaint.

============================================================
TASK 3 — Add yes_to_offer handling
============================================================

If last bot reply offered:
"Хотите подобрать банк под ваш случай?"

and user says:
"да", "давайте", "окей давайте", "хорошо"

then:
set:
intent=yes_to_offer_bank_selection

If debtor_type known:
- legal_entity -> active_scenario=bank_selection_yul
- individual -> active_scenario=bank_selection_fl

If debtor_type unknown:
ask:
"Подберём. Должник юрлицо или физлицо?"

If user says:
"окей давайте\nу меня ЮЛ"

then:
active_scenario=bank_selection_yul
known_slots.debtor_type=legal_entity
required_next_step=list_partner_banks_yul

Expected reply:
"Для юрлиц сейчас активные варианты — Альфа-Банк, ТКБ и Уралсиб. Т-Банк, МКБ и Росбанк сейчас на паузе. Если хотите, могу сразу сравнить тарифы."

============================================================
TASK 4 — Adjust ScenarioPolicy scoring by intent source
============================================================

Do not give hard score 100+ for semantic-only intent.

Rules:
- exact/regex hard intent can get high priority score.
- semantic intent can only boost scenario modestly unless supported by:
  - required terms
  - slots
  - active scenario compatibility
  - explicit topic switch phrases

Example:
direct_bank_objection:
- regex match "в чем выгода" -> strong score
- semantic match + required terms -> medium score
- semantic match without required terms -> rejected

Acceptance:
For "у меня ЮЛ должник нужен счет":
bank_selection_yul must outrank direct_bank_objection.

============================================================
TASK 5 — Explicit bank/account request overrides direct_bank_objection
============================================================

If active_scenario=direct_bank_objection but current message contains:
- "ЮЛ" / legal_entity
- "ФЛ" / individual
- "нужен счет"
- "нужен банк"
- "банк подобрать"
- "подешевле"
- "счет открыть"

then this is a topic switch to bank/account selection.

Switch:
- ЮЛ + low cost -> bank_selection_yul_low_cost
- ЮЛ + account/bank -> bank_selection_yul
- ФЛ + account/bank -> bank_selection_fl

Do not keep direct_bank_objection.
Do not force direct_bank_objection KB retrieval.

Acceptance:
"окей давайте\nу меня ЮЛ" after direct_bank_objection must switch to bank_selection_yul.

============================================================
TASK 6 — Fix forced_scenarios selection
============================================================

Currently forced_scenarios=['direct_bank_objection','partner_banks'] is applied when active_scenario=direct_bank_objection even if user switches topic.

Change:
Apply direct_bank_objection forced_scenarios only if:
- current accepted intent is direct_bank_objection
OR
- active_scenario=direct_bank_objection AND current message is a value-objection follow-up:
  - "подробнее"
  - "почему"
  - "в чем именно"
  - "вы не ответили"
  - "зачем с вами работать"

Do NOT apply direct_bank_objection forced_scenarios for:
- "нужен счет"
- "нужен банк"
- "ЮЛ"
- "ФЛ"
- "подобрать банк"
- "подешевле"
- "тарифы"
- "документы"

============================================================
TASK 7 — Add negative anchors / intent exclusions
============================================================

For direct_bank_objection, add excluded patterns:
- "нужен счет"
- "нужен банк"
- "подобрать банк"
- "у меня ЮЛ"
- "у меня ФЛ"

For bonus_interest, exclude unless terms contain:
bonus/percent/rate/yearly/interest.

For small_talk, exclude:
- "да"
- "нет"
- business phrases with bank/account/debtor terms.

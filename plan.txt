Ты работаешь с llm_messenger_bot-v3.

Текущие изменения уже запушены и частично работают:
- explicit_bank_selection работает;
- timing/timing_docs добавлены;
- intent-aware fallback добавлен;
- Timeweb provider уже использует max_completion_tokens для gpt-5*;
- render.md содержит {ref_section};
- ENABLE_LLM_SUMMARY=false по умолчанию.

Но осталось 4 проблемы:

1. GPT-5-mini возвращает пустой content, потому что весь max_completion_tokens уходит в reasoning_tokens.
В логах:
finish_reason=length
completion_tokens=300
reasoning_tokens=300
content=''
и то же на 450 токенах.

Решение:
- Добавить настройки:
  TIMEWEB_RENDER_MAX_TOKENS=3000
  TIMEWEB_ANALYZER_MAX_TOKENS=1500
  TIMEWEB_ENRICHMENT_MAX_TOKENS=1000
  TIMEWEB_SUMMARY_MAX_TOKENS=1500
  TIMEWEB_ESCALATION_MAX_TOKENS=2000
  TIMEWEB_REASONING_EFFORT=low

- В render_manager_text заменить ask_llm(..., max_tokens=300) на max_tokens=settings.TIMEWEB_RENDER_MAX_TOKENS.
- В dialog_analyzer использовать settings.TIMEWEB_ANALYZER_MAX_TOKENS.
- В llm_enrichment использовать settings.TIMEWEB_ENRICHMENT_MAX_TOKENS.
- В escalation_detector использовать settings.TIMEWEB_ESCALATION_MAX_TOKENS.
- Если model startswith gpt-5 и TIMEWEB_REASONING_EFFORT задан, попробовать добавить payload["reasoning_effort"] = "low".
- Если Timeweb вернул 400 из-за reasoning_effort, повторить без reasoning_effort.

2. Добавить query_mode="conditions".
Проблема:
"какие условия в ТКБ?"
"я спрашиваю подробнее какие там условия"
сейчас уходит в specific_bank и отвечает только opening_fee/monthly_fee.

Добавить regex:
_CONDITIONS_QUERY_RE = re.compile(
    r"(услови\\w*|подробнее|поподробнее|что\\s+там|расскаж\\w*|что\\s+входит|нюанс\\w*)",
    re.I | re.U,
)

Если есть bank_name/_last_bank и CONDITIONS_QUERY_RE:
decision = {
    "stage": "PRESENTATION",
    "action": "ANSWER",
    "query_mode": "conditions",
    "needs_kb": True,
    "needs_handoff": False,
    "confidence": 0.95,
}

Для fact_retriever:
QUERY_MODE_FILTER_MAP["conditions"] = ["pricing", "bonus", "docs", "feature", "constraint", "selection", "availability"]

Для plan_builder:
qmode == "conditions" должен собрать:
- bank
- client_type
- opening_fee
- monthly_fee
- transfer_fee
- bonus_rate
- docs/features/constraints кратко
intent = "conditions"

Для renderer:
добавить _render_conditions_static(plan).

Пример fallback:
"По ТКБ для юрлица условия такие: открытие 2800 рублей, ведение 2090 в месяц, платежи на юрлица — 33 рубля электронно. Плюс есть бонус на остаток. Что разобрать подробнее — платежи, документы или сроки?"

3. Улучшить fallback для ФЛ bank_selection.
Сейчас:
"сейчас хороший вариант — ткб. рассматриваем?"

Нужно:
"Для физлица сейчас основной рабочий вариант — ТКБ: открытие 1500 рублей, ведение бесплатно. Важный нюанс — расходные операции лучше заранее согласовывать с юристами банка. Смотрим тарифы подробнее?"

4. Убрать из intro фразу "живой человек, не бот".
Заменить intro на:
"Я Алексей, менеджер компании «В плюсе». Помогаем арбитражным управляющим открывать счета для должников: подбираем банк, сверяем условия и документы. Для кого сейчас подбираем счёт?"

Дополнительно:
- Добавить CRM_ENABLED=false для локальных тестов.
- Если CRM_ENABLED=false, maybe_escalate не должен вызывать Bitrix, но должен ставить slots["_escalation_sent"]=True.
- Bitrix ACCESS_DENIED не должен валить worker.

Acceptance criteria:
1. Timeweb gpt-5-mini перестаёт массово возвращать пустой content за счёт max_completion_tokens=3000+.
2. Если content всё равно пустой, intent-aware fallback отвечает по смыслу.
3. "какие условия в ТКБ?" → conditions, не просто pricing.
4. "я спрашиваю подробнее какие там условия" → conditions.
5. ФЛ bank_selection отвечает не "ткб. рассматриваем?", а кратко раскрывает ТКБ.
6. Intro не говорит "живой человек, не бот".
7. Handoff работает, но локально Bitrix можно отключить через CRM_ENABLED=false.

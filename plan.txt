Ты работаешь с llm_messenger_bot-v3.

Цель:
Корректно передать системные инструкции в LLM, убрать двусмысленность между request_data/handoff и заставить код запускать escalation, когда клиент реально готов открыть счёт.

Проблемы из живого теста:
1. Клиент говорит: “ну какие еще, счет открыть”.
   Brain возвращает action=request_data, handoff=false.
   Бот просит документы, но не запускает escalation.
2. Клиент говорит: “счет открыть”.
   Бот пишет “Давайте приступим...” как будто сам откроет счёт.
   Это запрещено бизнес-правилом.
3. System prompt говорит “не копируй CONTEXT_DO_NOT_COPY”, но фактический user payload передаётся просто как JSON без тега.
4. Бот повторяет представление/имя и плохо отвечает на “ты бот?”.
5. Нужно чётко разделить:
   - bot reply клиенту
   - state update
   - handoff/escalation action
   - request_data action
6. Китайский текст можно не фиксить глубоко, но нужно добавить language validator: ответ только на русском.

============================================================
2. Разделить request_data и handoff
============================================================

Сейчас action=request_data не запускает escalation.
Нужно определить правило:

request_data = бот просит минимальные данные, но пока не передаёт менеджеру.
handoff = бот передаёт менеджеру.

Но для фраз:
- “счет открыть”
- “откроем?”
- “как открыть?”
- “хочу открыть”
- “давайте открыть”
- “оформляем”
- “готов начать”
- “подключите менеджера”
- “позовите человека”
- “что дальше”
после выбора банка/условий должно быть:
action=handoff
handoff.needed=true

Если данных мало, reply может звучать так:
“Да, поможем оформить. Для старта нужен ИНН или название должника — подключу старшего менеджера, он доведёт до открытия.”

То есть handoff не требует, чтобы все данные уже были собраны.

Acceptance:
User: “ну какие еще, счет открыть”
→ action=handoff
→ handoff.needed=true
→ maybe_escalate called.

User: “счет откройте мне”
→ action=handoff
→ handoff.needed=true.

3. Добавить post-brain handoff override в коде
============================================================

Файл:
app/processing/message_processor.py
или app/services/response_validator.py

Даже если LLM вернула action=request_data и handoff=false, код должен проверить явные фразы открытия.

Добавить helper:

OPEN_ACCOUNT_EXPLICIT_RE = re.compile(
    r"(сч[её]т\s+откр|открыть\s+сч[её]т|откроем|оформляем|давайте\s+откр|хочу\s+откр|готов\s+откр|как\s+откр|что\s+дальше)",
    re.I | re.U,
)

def should_force_handoff(user_text: str, brain_result: dict, memory: dict) -> bool:
    if not OPEN_ACCOUNT_EXPLICIT_RE.search(user_text or ""):
        return False

    # НЕ force handoff, если active_task — comparison/transfer_fee
    active_task = (memory or {}).get("active_task") or {}
    if active_task.get("type") in ("transfer_fee_quote", "bank_comparison"):
        return False

    return True

После run_conversation_brain:
if should_force_handoff(user_text, brain_result, memory):
    brain_result["action"] = "handoff"
    brain_result["handoff"] = {"needed": True, "reason": "ready_to_open"}

Acceptance:
Даже если LLM ошиблась и вернула request_data, код поднимет handoff.

4. Исполнить handoff в message_processor
============================================================

Файл:
app/processing/message_processor.py

После brain_result:

handoff = brain_result.get("handoff") or {}
if brain_result.get("action") == "handoff" or handoff.get("needed"):
    reply = brain_result.get("reply") or _build_handoff_bridge(slots, "ready_to_open")
    await send_bot(...)

Важно:

- maybe_escalate вызывается после/до отправки, но не должен валить job;
- если CRM_ENABLED=false, логируем skip, но считаем handoff состоявшимся локально.

Acceptance:
В логах после “счет открыть” видно:
Brain action=handoff или forced handoff
maybe_escalate called / CRM disabled skip
_escalation_sent=True

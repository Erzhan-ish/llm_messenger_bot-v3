Ты работаешь с проектом llm_messenger_bot-v3.

Цель: стабилизировать текущую архитектуру controlled generation на Timeweb. Не переводить проект на локальную Llama/Ollama. Timeweb пока остаётся основным LLM-провайдером.

Главная архитектурная идея:
- Правила, slots и router решают, ЧТО делать.
- KB/RAG даёт факты, ЧТО можно говорить.
- LLM свободен только в формулировке текста.
- Validator проверяет, что LLM не придумал факты.
- Handoff/CRM/escalation остаются в коде, не в LLM.

Не переписывай проект полностью. Исправь точечно текущие слабые места:
1. Timeweb возвращает пустой ответ.
2. Вопросы про сроки открытия уходят в тарифы.
3. Multi-intent “сроки + документы” обрабатывается неполно.
4. Fallback отвечает не по intent.
5. Бот повторяется и снова пишет тарифы вместо ответа на вопрос клиента.

ЗАДАЧА 1. Починить Timeweb provider
Файл: app/llm/providers/timeweb.py

Проблема:
В логах LLM часто возвращает:
LLM raw response (len=0): ''
Также бывает:
502 Bad Gateway

Сейчас provider почти не диагностирует пустой content. Нужно понять, что реально возвращает Timeweb, и сделать запрос совместимым с gpt-5/gpt-5-mini.

Что сделать:

1. Добавить условную сборку payload для gpt-5 моделей.

Если model начинается с "gpt-5":
- использовать max_completion_tokens
- НЕ отправлять temperature
- НЕ отправлять top_p

Для остальных моделей:
- использовать max_tokens
- можно оставить temperature/top_p

Пример:

def _is_gpt5_model(model: str | None) -> bool:
    return bool(model and model.lower().startswith("gpt-5"))

limit = max_tokens if max_tokens is not None else 450

payload = {
    "model": self.model,
    "messages": normalized,
    "stream": False,
}

if _is_gpt5_model(self.model):
    payload["max_completion_tokens"] = limit
else:
    payload["max_tokens"] = limit
    payload["temperature"] = 0.55
    payload["top_p"] = 0.90

2. Добавить безопасный парсер ответа.

После response.json():

- достать choices[0]
- достать message.content
- если content — list, собрать text parts
- trim
- если content пустой, залогировать:
  - status_code
  - finish_reason
  - usage
  - message
  - raw JSON целиком, но аккуратно без секретов

Пример:

choice = (data.get("choices") or [{}])[0]
message = choice.get("message") or {}
content = message.get("content")

if isinstance(content, list):
    content = "\n".join(
        part.get("text", "") if isinstance(part, dict) else str(part)
        for part in content
    )

content = (content or "").strip()

if not content:
    logger.warning(
        "Timeweb returned empty content | status={} | finish_reason={} | usage={} | message={} | raw={}",
        response.status_code,
        choice.get("finish_reason"),
        data.get("usage"),
        message,
        data,
    )
    return ""

return content

3. Добавить 1 retry для временных ошибок 502/503/504.

Если Timeweb вернул 502/503/504:
- подождать 0.5–1 сек
- попробовать ещё один раз
- если снова ошибка, не валить весь worker, а вернуть "" или controlled exception, чтобы renderer ушёл в fallback.

4. Логировать краткую информацию о запросе:
- model
- number of messages
- max token field used: max_tokens или max_completion_tokens
- response status

Не логировать токены авторизации.

Acceptance:
- При пустом ответе Timeweb в логах видно raw JSON и finish_reason.
- При 502 один раз делается retry.
- gpt-5-mini не получает temperature/top_p/max_tokens.
- Worker не падает от 502, а уходит в безопасный fallback.

Ты работаешь с llm_messenger_bot-v3.

Цель:
Переделать поиск по базе знаний так, чтобы он не просто возвращал случайные top-k чанки, а умел распознавать все сценарии из KB и отдавать все обязательные факты по каждому найденному сценарию.

Важно:
Не возвращаем старый semantic routing.
LLM всё ещё думает и пишет.
Код должен:
- построить структурированный scenario/fact index;
- найти candidate scenarios;
- собрать полный fact_pack по ним;
- передать brain чистые факты;
- проверить, что ответ не потерял обязательные факты.

============================================================
1. Расширить формат KB
============================================================

В knowledge_base.txt для каждого CHUNK добавить поля:

SCENARIO:
ANSWER_HINT:
NEXT_QUESTION:

Пример:

---CHUNK---
TYPE: constraint
SCENARIO: debtor_card_realization
TOPIC: realization_card
CLIENT_TYPE: ФЛ
ALIASES: карта карточка реализация имущества должник списывают долги
TAGS: card debtor realization financial_manager
FACT: Если у гражданина введена реализация имущества, новая банковская карта оформляется и подписывается исключительно финансовым управляющим.
ANSWER_HINT: Не путать карту со снятием наличных. Если клиент спрашивает карту, объяснить роль финансового управляющего.
NEXT_QUESTION: Реализация имущества уже введена?

Для тарифов:

---CHUNK---
TYPE: pricing
SCENARIO: uralsib_yul_conditions
BANK: Уралсиб
CLIENT_TYPE: ЮЛ
FIELD: opening_fee
TOPIC: account_opening
VALUE_NUM: 3500
ALIASES: уралсиб юрлицо условия тариф открытие счет
FACT: В Уралсибе для ЮЛ открытие счёта стоит 3500 руб.

Acceptance:
- KB loader парсит SCENARIO, ANSWER_HINT, NEXT_QUESTION.
- KBChunk содержит scenario_id, answer_hint, next_question.

============================================================
3. Создать ScenarioFactIndex
============================================================

Файл:
app/knowledge_base/scenario_index.py

Реализовать:

@dataclass
class ScenarioMatch:
    scenario_id: str
    score: float
    reasons: list[str]
    matched_aliases: list[str]

class ScenarioFactIndex:
    def __init__(self, chunks: list[KBChunk]):
        self.by_scenario: dict[str, list[KBChunk]]
        self.by_topic: dict[str, list[KBChunk]]
        self.by_bank: dict[str, list[KBChunk]]
        self.by_client_type: dict[str, list[KBChunk]]
        self.alias_to_scenarios: dict[str, set[str]]

    def match_scenarios(user_text, memory, current_entities) -> list[ScenarioMatch]
    def get_chunks_for_scenario(scenario_id, bank=None, client_type=None) -> list[KBChunk]
    def build_fact_pack(matches, memory, current_entities) -> dict

match_scenarios должен учитывать:
- aliases
- tags
- topic
- current_entities.mentioned_bank
- current_entities.mentioned_client_type
- memory.last_topic
- memory.active_task
- exact phrase matches
- hybrid search score как дополнительный сигнал, но не единственный

Важно:
Scenario index не принимает финальное решение за LLM.
Он только собирает candidate scenarios and facts.

============================================================
5. Переписать retrieve_context_for_brain
============================================================

Файл:
app/services/fact_retriever.py

Сейчас retrieve_context_for_brain делает top-k поиск и возвращает chunks.
Нужно сделать 2 слоя:

A. scenario_matches:
scenario_matches = kb.scenario_index.match_scenarios(user_text, memory, current_entities)

B. scenario_fact_pack:
scenario_pack = kb.scenario_index.build_fact_pack(scenario_matches, memory, current_entities)

C. raw_kb_facts:
оставить hybrid top-k как дополнительный источник, но не основной.

Возвращаемая структура должна быть не просто list[dict], а лучше:

{
  "scenario_matches": [...],
  "scenario_facts": {...},
  "raw_kb_facts": [...]
}

Если нельзя сразу менять интерфейс, можно временно:
- raw_kb_facts оставить list;
- scenario_facts положить в context_builder.fact_pack.

Acceptance:
На запрос “Уралсиб вроде нормально, какие там условия?”
scenario_facts содержит все ключевые факты Уралсиба для ЮЛ:
- opening_fee 3500
- monthly_fee 1600
- transfer_to_yul 35
- operation_control_fee 150
- docs, если есть
- bonus, если есть

6. Fact_pack должен строиться из KB, не из hardcoded Python
============================================================

Файл:
app/services/context_builder.py

Сейчас там hardcoded:
_BANK_PRICING_YUL
_BANK_PRICING_FL
_CARD_RULES
_PARTNER_BANKS

Нужно постепенно заменить:

partner_banks = scenario_index facts where SCENARIO=partner_banks
bank_pricing_yul = facts where scenario in legal_entity_bank_selection / *_yul_conditions
bank_pricing_fl = facts where scenario in individual_bank_selection / *_fl_conditions
card_rules = scenario debtor_card_realization
advance_opening = scenario advance_opening

На переходном этапе можно оставить hardcoded fallback, но приоритет должен быть у KB.

Acceptance:
Если knowledge_base.txt обновили тариф Уралсиба, fact_pack меняется без правки Python-кода.

9. Добавить validation на completeness
============================================================

Файл:
app/services/response_validator.py

Если answer_contract или scenario_facts имеют required facts:
- проверять, что reply содержит обязательные факты или хотя бы не противоречит им.

Примеры:
- partner_banks: должны быть Альфа-Банк, ТКБ, Уралсиб.
- debtor_card_realization: должны быть “реализация имущества” + “финансовый управляющий”.
- uralsib_yul_conditions: если клиент спросил “условия”, reply должен содержать opening/monthly или спросить, что именно интересует, но не generic fallback.
- account_type_difference: reply не может быть “Как я могу помочь?”

Acceptance:
Generic replies не проходят при наличии scenario_facts.

============================================================
FINAL ACCEPTANCE
============================================================

Готово, если:
1. KB поддерживает SCENARIO / ANSWER_HINT / NEXT_QUESTION.
2. ScenarioFactIndex строится при загрузке KB.
3. retrieve_context_for_brain возвращает не только top-k chunks, но и scenario_matches + scenario_facts.
4. fact_pack строится из KB, а не только из hardcoded Python.
5. Все основные сценарии распознаются через aliases/tags/scenario_id.
6. По найденному сценарию возвращаются все обязательные факты, а не только top-k.
7. Обновление knowledge_base.txt меняет поведение без правки Python-кода.
8. Есть coverage tests на все сценарии.

Задача: сделать речь бота естественнее — убрать обязательный вопрос в конце каждого ответа.

Проблема:
Сейчас в pipeline.md / BRAIN_SYSTEM_PROMPT и answer_contract слишком жёстко прописано:
- “1–3 предложения, один вопрос в конце”
- next_question ожидается почти всегда
- validator/fallback могут считать отсутствие вопроса ошибкой

Из-за этого бот звучит неестественно:
- клиент дал согласие → бот всё равно спрашивает
- клиент отправил данные → бот всё равно спрашивает
- клиент попрощался → бот всё равно продолжает
- клиент готов открыть счёт → бот вместо перехода задаёт лишний вопрос

Нужно заменить правило “всегда вопрос” на “вопрос только если он нужен”.

============================================================
1. Смягчить BRAIN_SYSTEM_PROMPT / pipeline.md
============================================================

Было:
“Пиши коротко: 1–3 предложения, один вопрос в конце.”

Стало:
“Пиши коротко: обычно 1–3 предложения. Задавай уточняющий вопрос в конце только если он реально нужен: чтобы собрать недостающие данные, выбрать банк, уточнить тип клиента или продвинуть клиента к следующему шагу. Если клиент уже дал данные, подтвердил выбор, согласился на оформление, попрощался или просто поблагодарил — вопрос не нужен.”

Добавить правило:

Не задавай вопрос ради вопроса.
Если следующий шаг уже понятен — подтверди его и действуй.

Примеры:

User: “ИНН 1234567890”
Good:
“Принял ИНН, передам менеджеру для проверки.”

Bad:
“Принял ИНН. Что ещё подсказать?”

User: “Уралсиб подходит, оформляем”
Good:
“Отлично, Уралсиб фиксируем. Подключу старшего менеджера, он доведёт по документам и открытию.”

Bad:
“Отлично, Уралсиб фиксируем. Документы подсказать?”

User: “спасибо, понял”
Good:
“Пожалуйста, обращайтесь.”

Bad:
“Пожалуйста. Что ещё хотите уточнить?”

============================================================
2. Сделать next_question опциональным
============================================================

В answer_contract:
next_question может быть строкой или null.

Пример:

{
  "next_question": null
}

Если next_question=null:
- LLM не должна придумывать вопрос сама;
- validator не должен требовать вопрос;
- fallback не должен автоматически добавлять вопрос.

Если next_question задан:
- LLM может использовать его, если вопрос уместен;
- но даже тогда вопрос не обязателен, если клиент уже дал ответ или готов к handoff.

============================================================
3. Добавить question_policy в answer_contract
============================================================

Вместо одного поля next_question добавить/поддержать:

{
  "question_policy": "required|optional|forbidden"
}

Правила:

required:
- нужно собрать критически недостающую информацию
- например: тип клиента неизвестен, сумма перевода неизвестна, банк не выбран

optional:
- можно задать вопрос, если это помогает продолжить диалог
- например: “документы подсказать?”, “сравнить с другим банком?”

forbidden:
- вопрос в конце не нужен
- клиент дал данные
- клиент согласился на handoff
- клиент попрощался
- клиент сказал “спасибо”
- клиент явно попросил открыть счёт
- бот просто подтверждает принятие информации

Примеры:

1. Клиент спрашивает список банков:
question_policy=required
next_question="Счёт подбираем для юрлица или физлица?"

2. Клиент спрашивает тарифы:
question_policy=optional
next_question="Документы подсказать?"

3. Клиент говорит “оформляем”:
question_policy=forbidden
next_question=null

4. Клиент говорит “спасибо”:
question_policy=forbidden
next_question=null

============================================================
4. Обновить response_validator
============================================================

Validator не должен требовать вопрос в каждом ответе.

Добавить проверки:

Если question_policy="forbidden":
- reply не должен заканчиваться вопросом
- если reply содержит лишний вопрос → validation_error="unnecessary_question"

Если question_policy="required":
- reply должен содержать вопрос или явный запрос данных
- если нет → validation_error="missing_required_question"

Если question_policy="optional":
- вопрос допустим, но не обязателен

Acceptance:
- “Принял ИНН, передам менеджеру.” проходит validator.
- “Уралсиб фиксируем, подключу менеджера.” проходит validator.
- “Спасибо, обращайтесь.” проходит validator.
- Лишний вопрос после “спасибо” блокируется.

============================================================
5. Обновить context_fallback
============================================================

Fallback сейчас может добавлять вопрос автоматически.
Нужно:
- смотреть answer_contract.question_policy
- если forbidden → не добавлять вопрос
- если required → добавить нужный вопрос
- если optional → добавить только если ответ без него выглядит оборванным

Пример handoff fallback:

Good:
“Хорошо, поможем открыть. Подключу старшего менеджера, он доведёт по документам и оформлению.”

Bad:
“Хорошо, поможем открыть. Что ещё подсказать?”

6. Обновить conversation_brain prompt
============================================================

Добавить блок:

═══ ВОПРОС В КОНЦЕ ═══
Не каждый ответ должен заканчиваться вопросом.
Задавай вопрос только если:
- не хватает данных;
- нужно выбрать банк;
- нужно уточнить тип клиента;
- нужно продвинуть клиента к следующему шагу.

Не задавай вопрос, если:
- клиент дал данные;
- клиент подтвердил выбор;
- клиент готов к оформлению;
- клиент попрощался;
- клиент просто сказал спасибо;
- action=handoff или stop;
- answer_contract.question_policy=forbidden.

Если question_policy=forbidden — заверши ответ утверждением, без вопроса.

# Проекты / Projects

Каждый проект — это отдельная «личность» бота: своя база знаний, свой промпт, свои настройки.
Код и инфраструктура не меняются — только файлы конфигурации.

## Структура проекта

```
projects/
└── my_project/
    ├── system_prompt.md       # кто такой бот и как отвечает
    ├── knowledge_base.txt     # факты, которые он знает
    └── escalation_prompt.md  # (опционально) когда передавать живому человеку
```

## Подключение проекта

В файле `.env` укажи три переменные:

```env
KB_SOURCE_PATH=projects/my_project/knowledge_base.txt
LLM_SYSTEM_PROMPT_PATH=projects/my_project/system_prompt.md
ESCALATION_PROMPT_PATH=projects/my_project/escalation_prompt.md

# Текст сообщения клиенту при передаче менеджеру
HANDOFF_REPLY=Передаю вас специалисту, он поможет дальше.
```

Перезапусти сервер — бот стал другим.

## Файл 1: `system_prompt.md`

Определяет личность бота: имя, роль, стиль ответов.

**Обязательные части:**

```markdown
Ты — [Имя], [роль] компании «[Название]».

[Описание задачи бота в 1–2 предложениях.]

## Главный принцип

Все конкретные данные ([что именно]) бери только из блока KNOWLEDGE,
который передаётся вместе с запросом.

Если точного ответа в KNOWLEDGE нет — не выдумывай.

## Как отвечать

- Обычно 2–4 предложения.
- [правила стиля, тона, обращения]
```

## Файл 2: `knowledge_base.txt`

База фактов. Каждый факт — отдельный блок, начинающийся с `---CHUNK---`.

**Формат блока:**

```
---CHUNK---
TYPE: <тип>
TOPIC: <тема>
FACT: <основной текст факта — то, что попадёт в ответ>
TAGS: слово1 слово2 слово3
```

**Поля:**

| Поле | Обязательное | Описание |
|------|-------------|----------|
| `TYPE` | да | Тип факта — для фильтрации. Придумай свои: `product`, `faq`, `location`, `price` и т.д. |
| `TOPIC` | да | Тема — используется при поиске |
| `FACT` | да | Текст факта, который пойдёт в ответ клиенту |
| `TAGS` | нет | Ключевые слова через пробел — улучшают точность поиска |

**Правила написания фактов:**
- Один блок = один факт или одна тема
- Пиши конкретно: адреса, цены, часы, условия — без воды
- Чем точнее `TAGS`, тем лучше поиск подходящих блоков под вопрос

## Файл 3: `escalation_prompt.md` (опционально)

Промпт для LLM-классификатора, который решает — передавать ли диалог живому менеджеру.

Если файл не указан, используется дефолтный из `app/llm/prompts/escalation_prompt.md`.

Меняй, если хочешь настроить триггеры под свою предметную область:
- заменить примеры фраз готовности купить/записаться
- убрать/добавить причины эскалации

**Формат ответа классификатора должен остаться неизменным** (JSON-структура).

## Пример: `projects/city_guide/`

Готовый пример гида по Санкт-Петербургу. Подключается так:

```env
KB_SOURCE_PATH=projects/city_guide/knowledge_base.txt
LLM_SYSTEM_PROMPT_PATH=projects/city_guide/system_prompt.md
HANDOFF_REPLY=Соединяю вас с живым гидом, он ответит на все вопросы.
```
